# Workspaces

*A workspace is the top-level container that holds your projects and folders. Every user has a private workspace. Companies can additionally enable a shared workspace, where every member sees and works on the same projects instead of exchanging copies.*

---

## Overview

| *Workspace* | *Who sees it* | *Where it appears* |
|-------------|---------------|--------------------|
| **Private workspace** | Only you | Listed under your initials in the workspace selector; its root folder is called **Home** |
| **Shared workspace** | Every member of your company | Listed under the company logo (or a home icon) with the name chosen by your administrator |

The shared workspace is enabled per company. If the workspace selector lists only your private workspace, the shared workspace has not been turned on for your company: contact your Application Engineer to enable it.

```{seealso}
The Python API can create projects directly in either workspace. See {ref}`User Guide: Workspaces <workspaces>` and the snippet {ref}`Submit a Project to a Shared Workspace <python_api_submit_to_shared_workspace>`.
```

## Switching Workspaces

*The workspace selector sits at the top of the left sidebar, below the search entry.*

```{image} ./Figures/workspace_selector.png
:alt: Workspace selector open in the left sidebar, listing the private Home workspace and the company shared workspace
:align: center
```

Open the selector and pick a workspace. Everything that lists or creates projects then acts inside the selected workspace:

- **Dashboard:** the **Recent** projects and the **New project** button.
- **Workspace page:** the **Project view** and **Files view** tabs, together with the folder tree shown in the sidebar.
- **Search:** searches the current workspace by default. When a shared workspace is enabled, the **Scope** option can search every workspace you have access to, and each result names the workspace it was found in.

The selection is remembered as you move between pages, so you keep working in the same workspace until you switch again.

```{note}
The **V1 (release-24.2 and older)** tab of the workspace page is shown only in the private workspace.
```

## Working in the Shared Workspace

*Projects in the shared workspace belong to the company rather than to one user.*

- **Visibility:** every member of the company can open, run, fork and organise any project in the shared workspace, and every member sees the same folder structure.
- **Drafts are locked while edited:** when a member opens a draft in a shared-workspace project, that draft is locked for the others. A second member who opens it sees the message *This draft is currently opened by [name]. Editing is disabled to prevent conflicts*, and the setup panels and the **Run** button are read-only until the first member leaves the draft.
- **Activity log:** create, move, duplicate, run and delete actions in the shared workspace are recorded with the member who performed them. Administrators review the log from the [Company workspace](../06.account-settings/04.company-workspace.md) page.

## Moving Projects Between Workspaces

*Projects can be moved in both directions, from your private workspace into the shared one and back.*

```{image} ./Figures/workspace_move_toolbar.png
:alt: Project view with five projects selected and the Move button highlighted in the toolbar
:align: center
```

To move projects:

1. Open the **Project view** of the workspace that currently holds the project.
2. Select the project, or several projects, and click **Move** in the toolbar. A single project can also be moved from its context menu.
3. In the **Move** dialog, pick the target workspace at the top of the folder picker, then the destination folder.
4. Confirm. The project disappears from the source list and shows a **Moving** label in the target workspace until the transfer completes.

```{image} ./Figures/workspace_move_dialog.png
:alt: Batch move dialog listing the selected projects on the left and the target workspace tabs with the folder tree on the right
:align: center
```

Before the move starts, Flow360 checks each selected project. Projects with active runs, running interpolations, or resources in an error state cannot be moved and are flagged in the dialog; move them once those runs have finished. A batch move accepts up to 50 projects at a time, and reports cannot be moved this way.

The **Location** field in a project's details panel offers the same choice of workspace and folder for a single project (see [Project settings](./07.project-settings.md)).
